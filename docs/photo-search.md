# Поиск аниме по скриншоту

## Использование и данные

Камера рядом с поиском открывает адаптивное окно. Она доступна гостям в обычной шапке, мобильной шапке и на странице `/search`.

Пользователь загружает JPG/PNG/WebP до 12 МБ, перетаскивает файл или вставляет изображение. Кнопка чтения буфера появляется только при наличии Clipboard API; отказ в доступе не блокирует загрузку. Обрезка поддерживает 16:9 и 4:3, перемещение рамки мышью/пальцем и доступные с клавиатуры ползунки. Изображения более 40 Мп отклоняются. Предпросмотр уменьшается до 1920 px по длинной стороне, отправляемый JPEG — до 1280 px и 2 МБ. Canvas удаляет метаданные исходного файла.

Файл отправляется **из браузера непосредственно** в `https://api.trace.moe/search?anilistInfo`, через multipart `image`. CORS проверен с Origin `https://animonster.su`. Ключи не используются. Нет серверного proxy для изображений и нет загрузки пользовательских фотографий в хранилище AniMonster. Перед кнопкой поиска показано уведомление о передаче кадра trace.moe. Сжатие/обрезка происходят локально. Закрытие окна, удаление и замена файла прерывают текущую операцию; ответы старых операций игнорируются.

Один клик — один запрос распознавания. Нет автоматических повторов или пакетного поиска. Зеркальный вариант доступен отдельной кнопкой при пустом или неуверенном результате. До трёх уникальных AniList ID сортируются по сходству; менее 90% отмечаются как неуверенные. Сходство не называется вероятностью. `episode` принимается как число, строка или отсутствующее значение, время сцены показывается только при корректных значениях. Превью допускаются только по HTTPS с `api.trace.moe` и `media.trace.moe`.

Обрабатываются квота/402, 429, Retry-After при его доступности браузеру, 5xx, сетевые ошибки, некорректные ответы и таймаут 45 секунд. Лимиты trace.moe не зашиты в код.

## Сопоставление с AniMonster

`POST /api/photo-search/resolve` принимает только 1–3 положительных числовых AniList ID. Изображения и произвольные URL не принимаются. JSON ограничен 1 КБ при чтении потока. Используются существующая проверка Origin и отдельный префикс счётчиков в `auth_limits`: до 30 запросов проверки каталога за минуту на IP. Регистрация не требуется.

Порядок сопоставления:

1. Уже имеющийся `anilist_id` в JSON `anime_cache`, если такая связь присутствует. Сейчас отдельной таблицы AniList-связей в проекте нет.
2. Сервер получает доверенные данные по этому ID из AniList GraphQL. MAL ID сопоставляется с **явным** `mal_id` нашего каталога. Равенство Shikimori ID и MAL ID не предполагается.
3. При отсутствии ID-связи требуется точное совпадение одного из основных названий AniList с названием/альтернативным названием каталога, совпадающий год и совместимый формат (TV, фильм, OVA, ONA, special, music). Общие синонимы франшизы AniList не используются для выдачи ссылки. Нечёткий поиск не выбирает сезон автоматически.
4. При нескольких кандидатах ссылка не выдаётся. Неоднозначность и недоступность проверки отличаются от сообщения «Пока нет в каталоге».

Данные AniList хранятся семь дней в существующем `catalog_page_cache`; при временном сбое доступны последние сохранённые сведения. Повторные одновременные запросы одного ID объединяются. На 429/5xx действует временная пауза запросов к AniList. В кэш не записываются заголовки, присланные браузером, или фотографии. Данные каталога не изменяются, новые аниме не создаются. Дополнительная таблица соответствий и миграция не требуются.

Кнопка ведёт на `/anime/[id]`. Параметры серии/плеера не добавляются: достоверного соответствия нумерации trace.moe и провайдеров плеера в проекте пока нет.

## Ограничения

trace.moe ищет визуально похожие сцены в своей базе. Кадры с монтажом, надписями, сильным кропом или фильтрами могут не распознаться. В базе есть не все аниме. Предпросмотры временные (по документации около пяти минут); ошибка картинки скрывает её, не ломая результат. Доступность и квота зависят от сервиса и IP пользователя. AniList используется для названий и проверки каталога; при его недоступности распознанные кадры всё равно показываются. Clipboard API и разрешения различаются между браузерами.

Документация: https://soruly.github.io/trace.moe-api/

## Проверки

Модульные/интеграционные проверки: `node --test tests/photo-search.test.mjs`. Они используют изолированный PostgreSQL (PGlite) и подменённый внешний transport, проверяя настоящий код сопоставления, SQL, API, Origin, размер тела и ограничение частоты.

Проверены настольный Chromium, Android/Pixel в Chromium и iPhone в WebKit через Playwright: JPG/PNG/WebP, обрезка 16:9/4:3, вставка и отказ в доступе к буферу, перетаскивание, повторы, зеркальный кадр, ошибки квоты/сети/5xx/таймаута, отмена, возврат фокуса, ссылки и вёрстка. Это эмуляция браузеров; проверка на физических устройствах отдельно не выполнялась. Отдельный живой тест официального изображения trace.moe прошёл без подмены API: `Gochuumon wa Usagi desu ka??`, сходство 99,2%, серия 1, сцена 4:32–4:42.

Полный набор тестов следует запускать с ограниченной конкуренцией в этой Windows/OneDrive-среде: `node --test --test-concurrency=2 tests/*.test.mjs`. Обычный массовый запуск здесь показал временные ошибки чтения файлов; повтор с двумя процессами прошёл. Полный lint содержит прежние ошибки в других файлах; lint файлов функции проходит. TypeScript и production build проверяются отдельно.

Итог проверки: 170/170 тестов (включая 12 тестов функции), TypeScript и production build проходят. Линтер файлов функции проходит; общий линтер остаётся красным из-за существующих ошибок в `lib/server/vpn.ts`, `components/community/profile-page.tsx` и старых тестах с непроверенными Promise.

## Обновление production

После публикации коммита, из существующего checkout на сервере, при чистом рабочем дереве:

```sh
git status --short
git rev-parse HEAD
git pull --ff-only
docker compose --env-file .env.production build app
docker compose --env-file .env.production up -d --no-deps app
docker compose --env-file .env.production logs --tail=100 app
```

Сохраните предыдущий SHA для отката. Новое приложение запускайте только после успешной сборки. Миграция и новые переменные окружения не нужны. Проверьте камеру в шапке и `/search`, распознавание одного кадра, обычный текстовый поиск и открытие страницы аниме. Эти команды в рамках задачи на production не выполнялись.
