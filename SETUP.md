# AniMonster — запуск и выпуск

## Локальная разработка

Требуется Node.js 22. Выполните `npm ci`, скопируйте `.env.example` в `.env` и запустите `npm run dev`. Если `DATABASE_URL` не задан, разработка автоматически использует локальную PGlite-базу в `.data/animonster`; вручную поднимать PostgreSQL для интерфейсной работы не нужно.

`OWNER_PREVIEW=true` создаёт только в development локальный профиль администратора. В production этот режим выключен независимо от входящих заголовков.

## Production на Timeweb Cloud

Для первого запуска достаточно одного облачного сервера Ubuntu: PostgreSQL, Next.js и Caddy запускаются отдельными контейнерами Docker Compose. DNS-записи `A` для домена позднее можно направить на публичный IP сервера. Откройте входящие TCP-порты 22, 80 и 443.

1. Установите Docker Engine с Compose plugin и загрузите проект в `/opt/animonster`.
2. Скопируйте `.env.production.example` в `.env.production`. Задайте длинный `POSTGRES_PASSWORD`; для запуска по IP оставьте `SITE_ADDRESS=http://31.77.10.81` и `SITE_URL=http://31.77.10.81`.
3. Выполните `docker compose --env-file .env.production up -d --build`. Контейнер PostgreSQL сначала проходит healthcheck, затем `migrate` применяет новые SQL-миграции, после чего запускаются приложение и Caddy.
4. Проверьте `http://31.77.10.81/api/health`, затем `docker compose --env-file .env.production ps` и `docker compose --env-file .env.production logs --tail=200 app`.

После подключения домена замените `SITE_ADDRESS` и `SITE_URL` на `animonster.su` и `https://animonster.su`. Если DNS указывает на сервер и порты 80/443 открыты, Caddy автоматически получает и продлевает публичный TLS-сертификат.

Секреты не входят в образ и Git. `OWNER_PREVIEW` в production должен оставаться `false`. Пока платёжная система не подключена, оставьте `PAYMENTS_ENABLED=false`.

## Первый администратор и режим доступа

Укажите числовой ID личного аккаунта VK в `ADMIN_VK_USER_ID`. При первом входе этого пользователя через VK ID аккаунт получает роль `admin`. В `/admin` можно назначать роли `Пользователь`, `Модератор`, `Администратор`, выдавать Plus на 31 день и блокировать аккаунты.

При `INVITE_REQUIRED=false` регистрация открыта без кода приглашения. Чтобы позднее вернуть закрытый режим, установите `INVITE_REQUIRED=true`; форма и сервер снова потребуют одноразовый инвайт. Аналогично `EMAIL_VERIFICATION_ENABLED=false` временно разрешает вход и все функции без подтверждения почты, а значение `true` возвращает проверку адреса.

Ссылка «Админка» отрисовывается только для `admin` и `moderator`. Сервер дополнительно защищает `/admin` и API: обычному пользователю возвращается 404. Менять роли может только `admin`; модератор может работать с жалобами, блокировками и Plus. Управление инвайтами появляется при `INVITE_REQUIRED=true`.

## VK ID

В кабинете [VK ID для бизнеса](https://id.vk.ru/business/go) создайте Web-приложение. Базовый домен: `animonster.su`. Доверенный Redirect URL: `https://animonster.su/api/auth/vk/callback`. В `.env.production` задайте `VK_CLIENT_ID`, `VK_CLIENT_SECRET` и `ADMIN_VK_USER_ID`.

VK ID показан в окне входа первым и крупной синей кнопкой. Email и пароль находятся в раскрывающемся альтернативном блоке. При открытой регистрации инвайт в обеих формах скрыт.

## Email

Подтверждение адреса и восстановление пароля отправляются через [Unisender Go Web API](https://godocs.unisender.ru/web-api-ref). Подтвердите домен отправителя, добавьте предложенные сервисом SPF/DKIM-записи и задайте `UNISENDER_API_KEY` и `EMAIL_FROM`. Пока email не подтверждён, профиль уже отображается, но комментарии, коллекция и другие записи заблокированы сервером.

## Каталог и видео

Метаданные и список серий загружаются динамически через AniLiberty, а интерфейс провайдера находится в `lib/server/providers.ts`. Ручного списка из 24 тайтлов нет. `KODIK_API_TOKEN` оставлен только для дополнительной озвучки и не является обязательным.

`MEDIA_PROXY_ENABLED=true` направляет HLS-плейлисты и видеосегменты через сервер AniMonster. Это позволяет зрителям открывать серии, когда CDN источника недоступен у их провайдера. Задайте отдельный случайный `MEDIA_PROXY_SECRET` длиной не менее 32 символов. `MEDIA_PROXY_HOSTS` содержит разрешённые CDN-хосты. При разрешённом `cache.libria.fun` шлюз также принимает его нумерованные узлы `cacheN.libria.fun`: источник перенаправляет разные видеофрагменты на разные узлы. Остальные адреса запрещены; не добавляйте произвольные домены. Учтите исходящий трафик сервера: при таком режиме весь видеопоток проходит через VPS.

AniMonster не хранит видеофайлы. Перед публичным коммерческим запуском требуется договор с правообладателем или лицензированным видеопровайдером. Доступность, реклама и права на конкретный тайтл контролируются подключённым источником.

## Проверки перед выпуском

Запустите `npm run lint`, `npm test`, `npm run build` и `npm audit --omit=dev --audit-level=high`. После выпуска проверьте открытую регистрацию по email, VK-вход, закрытый профиль, просмотр серии, комментарии, жалобу, выдачу роли и Plus из отдельного админского аккаунта.
