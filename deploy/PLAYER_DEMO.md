Сайт и актуальная база после переезда 24 октября: `177.3.218.227`. Публичный адрес — https://animonster.su/player-demo, вход через `31.77.10.81`.

Предыдущий релиз `/root/animonster-release-player-demo-20261025` и образ `animonster-app:player-demo-20261025` сохранены. Дамп перед миграцией функций: `/root/db-before-player-features-20261025.dump`, доступ только root.

25 октября прежний видеосервер `31.77.14.179` перестал отдавать HTTPS и SSH-баннер. Его файлы не удалялись. Первые четыре серии восстановлены на текущем сервере в `/var/lib/animonster-media/enhanced`; nginx отдаёт только `enhanced/published/` по `/demo-media/enhanced/`. Синхронизация старого каталога остановлена, чтобы не возвращать недоступные URL. 26 октября для загрузки выбраны все 19 серий этой раздачи; подготовка выполняется пакетным заданием, описанным ниже.

## Состав

- `/player-demo` и публичный `GET /api/player-demo`: только завершённые серии, озвучки, реальные качества, субтитры, спрайты превью и подготовленные MP4. Пути исходников не раскрываются. Клиент подхватывает новый каталог без перезагрузки.
- `PLAYER_DEMO_ENABLED=true` открывает страницу и блок на главной. `PLAYER_DEMO_CATALOG` выбирает JSON; для восстановленных видео — `/var/lib/animonster-media/enhanced/catalog.json`.
- Полный экран: стандартный API, нативный iOS и развёртывание внутри страницы как резерв. PiP зависит от поддержки браузера. Скорость 0.5–2, горячие клавиши, двойное касание по краям ±10 секунд, настройки субтитров.
- Пропуск OP/ED использует AniSkip v2 с проверкой длительности релиза (допуск 5 секунд), затем проверенные главы источника. На момент проверки AniSkip возвращал отсутствие данных для MAL 61316, серий 1/2. Длинную главу Intro автоматически опенингом не считаем. ED из главы Outro доступен. После титров сохраняются сцены, если интервал заканчивается раньше серии.
- `GET/POST /api/player-demo/progress`: приватный прогресс аккаунта между устройствами; локальная копия отдельно для гостя и каждого аккаунта. Старые офлайн-записи не перезаписывают свежие. Завершённая серия открывает следующую при возвращении.
- `GET/POST /api/player-demo/party`: отдельные комнаты демо до 10 зрителей, до 3 активных комнат ведущего, срок 12 часов. Нужен аккаунт. Только ведущий меняет серию, паузу, позицию и скорость; версия предотвращает перезапись старой командой. У каждого своя озвучка и качество. Опрос 2 секунды, heartbeat 15 секунд. Автовоспроизведение может требовать первого нажатия зрителя.
- `GET /api/player-demo/download`: **бесплатно всем**, включая гостей. Выдаёт только подготовленный MP4 выбранной озвучки/качества и субтитры. Основные загрузки AniLiberty сохраняют прежние правила Plus.
- Офлайн: MP4 скачивается диапазонами по 8 МиБ с проверкой Content-Range и докачкой; хранится в OPFS/IndexedDB. `/downloads` и модуль офлайн-плеера прогреваются до загрузки. SW v7 поддерживает холодный запуск `/downloads?id=…` без сети. Смотреть через «Загрузки» после полного скачивания. Хранилище привязано к браузеру и устройству, зависит от квоты; пользователь или браузер может его очистить.
- Миграция `0060_player_demo_features.sql` создаёт три отдельные таблицы. `0059_profile_social_visibility.sql` к этому выпуску не относится и на сервере не применялась. Платёжные флаги не менялись. На сервере PAYMENTS_ENABLED уже true; статическая ошибочная надпись о недоступности донатов заменена штатным BuySubscription с initialPlan=support и целью player. Тестовая финансовая транзакция не выполнялась.

## Все четыре серии одним файлом

`python3 /opt/animonster-media/demo-season-downloads.py` под `animonster-media:www-data`, umask 0027, CPUQuota 150%, MemoryMax 1536M готовит MP4 из готовых потоков сезона. Задание выпуска — `animonster-demo-season-downloads.service`. Перед каждой записью проверяется резерв 20% диска. Видео/звук копируются без повторного кодирования; добавляются четыре главы, встроенные русские mov_text-субтитры и faststart. Перед атомарной публикацией проверяются кодеки, длительность и границы всех глав. В каталоге появляются только завершённые файлы. Повторный запуск проверяет и использует существующие MP4, не меняя опубликованные байты.

Готовы 12 вариантов: AniStar, AniLibria, оригинал × 360/480/720/1080p. Размеры приблизительно 504 МБ, 698 МБ, 1.16 ГБ, 2.31 ГБ. В демо есть выбор «Все серии (4) / Только серия N». Кнопка сохраняет видео для сайта без сети; ссылка «Скачать MP4 на устройство» запускает обычное скачивание файла. В локальном разделе загрузок объединённый файл представлен одной карточкой «Серии 1–4»; офлайн-плеер имеет кнопки глав и запоминает глобальную позицию, переводя её в обычный прогресс серии при возврате онлайн.

`GET /api/player-demo/download?season=season-<hash>&voice=anistar&quality=720` бесплатно возвращает параметры конкретной версии сезона. Неверная версия или неподготовленное качество дают 404; запросы по `episode=N` сохраняют прежнее поведение. `season.id`, главы и описание источника сохраняются вместе с локальной загрузкой. При докачке используется этот неизменяемый источник, даже если текущий каталог уже расширился или сменил версию. ID разных версий не пересекаются. Старые файлы опубликованных версий удалять нельзя, пока они нужны уже начатым загрузкам. Новая миграция БД не требуется.

Проверки выпуска: 209 JS-тестов, Python-тесты сборки, canary API всех 12 вариантов без аккаунта, проверка последних диапазонов MP4 по HTTPS (206), декодирование всех трёх стыков в готовом MP4. Визуальная браузерная проверка не выполнялась из-за ранее отклонённого доступа. Предыдущий образ `animonster-app:player-feedback-20261025` сохранён.

## Обратная связь после просмотра

Миграция `0061_player_demo_feedback.sql` добавляет отдельную таблицу отзывов и покрытия просмотра. Она применяется отдельно от чужих незавершённых миграций после резервной копии. Резервная копия перед выпуском: `/root/db-before-player-feedback-20261025-073610.dump` (root, 0600). Предыдущий образ `animonster-app:player-season-20261025` сохранён для отката; таблицу при откате удалять не нужно.

Форма с оценкой 1–10 и необязательным комментарием до 2000 символов появляется после просмотра минимум 70% **каждой из трёх разных серий**. Считается объединение воспроизведённых интервалов: повторы не удваивают процент, перемотка и автопропуск не засчитываются. Работают оба режима шкалы и скорость воспроизведения. Учёт начинается с установки этого выпуска; старую позицию прогресса нельзя достоверно превратить в просмотренные интервалы.

`GET/POST /api/player-demo/feedback` использует текущий аккаунт или отдельный случайный HttpOnly/SameSite cookie гостя; в production cookie Secure. Scope в запросах предотвращает перенос старой телеметрии после смены аккаунта. Покрытие объединяется на сервере под блокировкой строки, отправка отзыва разрешается только при достижении порога. Для сериализованного JSON используется text → jsonb, а схема требует JSON-объект. Имена, IP и адреса почты гостей не собираются.

Данные локально сохраняются и синхронизируются каждые 30 секунд и при уходе со страницы. После достижения порога сбор покрытия останавливается. В полном экране, PiP и скрытой вкладке автоматическая форма ждёт возвращения к странице. При самостоятельном просмотре форма ставит видео на паузу и возвращает воспроизведение после закрытия. Комната не ставится на паузу ради одного зрителя. «Позже» откладывает предложение на 7 дней; после успешной отправки повторного запроса нет. Повтор POST не создаёт второй отзыв.

Отзывы, количество и средняя оценка доступны администратору в `/admin/player-feedback` и `GET /api/admin/player-feedback?offset=0` (50 записей на страницу). Остальным API возвращает 404. Комментарии выводятся обычным React-текстом; HTML не исполняется. Удаление аккаунта удаляет его отзыв через FK cascade. Браузерная проверка интерфейса ранее была отклонена политикой доступа; проверяются типы, unit/PGlite-тесты и настоящие HTTP-сценарии в canary.

## Сезон одним видео

`season` в каталоге содержит общую длительность, непрерывные `chapters` с номером серии и границами, общие озвучки/качества, совмещённые субтитры и превью. По умолчанию включён этот режим; кнопка «По отдельным сериям» возвращает обычный просмотр с сохранением позиции.

`python3 /opt/animonster-media/demo-season.py --root /var/lib/animonster-media/enhanced --public-prefix /demo-media/enhanced` создаёт единый HLS VOD. Подготовленные MP4 серий перепаковываются без повторного кодирования в непрерывные видеодорожку и аудиодорожки с общими временными метками. Это позволяет перематывать к поздним сериям без сброса времени на стыках. Создаются дополнительные HLS-сегменты; для скачивания подготовлены отдельные MP4 сезона. Публикуются только озвучки и качества, общие для всех включённых серий. Хешированные URL неизменяемы, каталог заменяется атомарно под import.lock. Главы используют проверенные длительности MP4 1080p; одинаковые длительности входов задаются при склейке всех качеств и озвучек. Рендиции проверяются на совпадение внутренних границ исходников.

Общая шкала и превью показывают номер серии и локальное время. Кнопки на шкале перемещают к началу серии. Прогресс и комнаты хранят прежние координаты «номер серии + секунда»; перевод в общую шкалу выполняется на клиенте. Автопропуск переводит интервалы текущей серии в глобальное время, сохраняя сцены после титров. В режиме сезона непрерывное воспроизведение включено; для паузы между сериями используется обычный режим. Скачивание бесплатно: отдельные серии или весь опубликованный набор одним MP4.

Проверки: npm test; python tests/demo-season-assets.test.py; tsc; lint изменённых файлов; canary HTTP с двумя временными аккаунтами. Браузерная проверка отклонена политикой доступа, поэтому визуальная и мобильная приёмка не подтверждены.

## Восстановление и дополнительные файлы

`animonster-demo-origin-torrent.service` — изолированный Transmission с RPC на loopback; `animonster-demo-recovery-v2.service` ждёт завершения выбранных файлов, публикует 1080p, превью и офлайн, затем готовит остальные качества. `scripts/prepare-demo-recovery.py` содержит текущую процедуру. `scripts/demo-media-assets.py` использует явные границы сегментов оригинала, сверяет длительности, публикует каталог атомарно. Незавершённый вариант не виден зрителям. Задания ограничены памятью 1536 МиБ и низким приоритетом CPU/диска. Для текущего финального задания выделено до двух CPU с CPUWeight=10; запросы сайта имеют обычный приоритет. Первые два исходника и четыре качества готовы. Все четыре исходника получены, торрент остановлен. Для серий 1/2 подготовлены четыре качества; 3/4 первоначально опубликованы в 1080p с бесплатными скачиваниями. Дополнительные качества готовятся отдельным заданием, после чего сезон перепаковывается с расширенным набором качеств. Процесс можно повторить с теми же root/spec/public-prefix: готовые проверенные варианты используются повторно.

Для сборки добавлен временный swap `/swap-animonster-build` 3 ГиБ, не в fstab. Docker build ограничен `--memory=3g --memory-swap=5g`. Не удалять swap, пока им пользуются процессы. Сервис сайта во время обработки остаётся отдельным контейнером.

## Загрузка и импорт

FFmpeg, Python 3, Transmission и aria2 устанавливаются пакетным менеджером сервера. Торрент-сервис работает от `animonster-media`, RPC привязан только к `127.0.0.1:9092`. В Ubuntu профиль AppArmor для Transmission должен разрешать запись только в `/var/lib/animonster-media/downloads/` и `/var/lib/animonster-media/transmission/`; профиль не отключать.

```sh
runuser -u animonster-media -- python3 /opt/animonster-media/demo-torrent.py INFO_HASH
runuser -u animonster-media -- python3 /opt/animonster-media/demo-torrent.py INFO_HASH --files 18,1
python3 /opt/animonster-media/demo-media.py --probe /path/to/episode.mkv
```

Индексы файлов выводятся с нуля. Их порядок в раздаче может отличаться от номера серии. aria2 при необходимости получает только метаданные раздачи, сами выбранные файлы скачивает Transmission. Перед выбором проверяется размер и запас 20% диска.

Создать приватную спецификацию `/var/lib/animonster-media/specs/rezero.json`, сверив индексы дорожек через `--probe`:

```json
{
  "title": "Re:Zero — жизнь с нуля в другом мире · ТВ-4",
  "episodes": [
    {
      "number": 1,
      "title": "Серия 1",
      "sources": [
        {
          "file": "/var/lib/animonster-media/downloads/episode-01.mkv",
          "voices": [
            { "id": "anistar", "title": "AniStar · Дубляж", "audio_stream": 1 },
            {
              "id": "original",
              "title": "Японский оригинал",
              "audio_stream": 2
            }
          ],
          "subtitles": [
            { "stream": 3, "title": "Русские · DEEP", "language": "ru" }
          ]
        }
      ]
    }
  ]
}
```

Это пример формы, а не подтверждение фактических индексов. Для отдельных релизов добавить несколько `sources`; `voices[].id` должны быть уникальны в серии. Внешние SRT поддерживаются через `subtitles[].file` вместо `stream`. Интервалы пропуска задаются в секундах отдельно в каждой озвучке: `"opening":{"start":90,"stop":180}` — только после проверки.

```sh
systemctl start animonster-media-import@rezero
journalctl -fu animonster-media-import@rezero
```

Импорт последовательно кодирует 480/720/1080 без апскейла, один видеоряд используется всеми его аудиодорожками. Ограничения: одно задание, один CPU, 1 ГБ RAM, низкий приоритет диска. Только завершённая серия атомарно попадает в `published/` и `catalog.json`. Повторный импорт готовых исходников не дублирует результат.

Для первоначальной проверки совместимого 1080p H.264 8-bit доступен `--fast-1080`: перепаковка без повторного кодирования. В этом режиме доступен только 1080p. Обычный импорт позднее заменит запись каталога комплектом адаптивных качеств; старые файлы сохраняются для уже начавших просмотр.

## Выпуск и откат

В прежней схеме служба `animonster-demo-catalog-sync.service` на сервере сайта копирует завершённый каталог каждые 30 секунд (сейчас таймер остановлен) через HTTPS, проверяя сертификат. Запрос идёт непосредственно на видеосервер с SNI `animonster.su`; его `/demo-media/catalog.json` разрешён только с IP сервера сайта и localhost. Публикация локального каталога атомарная; при сбое предыдущая версия сохраняется. Синхронизация работает от отдельного пользователя `animonster-catalog` с правом записи только в каталог метаданных. Nginx прокси медиасегментов использует `proxy_ssl_verify on` и `proxy_ssl_verify_depth 3`.

Перед включением проверить настоящую серию в двух озвучках, её манифесты/сегменты, WebVTT и воспроизведение. Тестовые тоны из `validation/` не публиковать и не добавлять в каталог демо.

Для сайта применить `deploy/compose.player-demo.yaml` вместе с существующими Compose-файлами. Каталог и медиа монтируются read-only; nginx отдаёт медиа напрямую. Сначала проверить отдельный контейнер на loopback, затем заменить только сервис `app` с `--no-deps`. Миграция 0060 применяется отдельно после резервной копии; полный автоматический migrate не запускать при наличии чужих незавершённых миграций.

```sh
cd /root/animonster-release-player-features-20261025
docker compose --env-file .env.production --env-file .player-demo.env -p animonster -f compose.yaml -f compose.override.yaml -f deploy/compose.player-demo.yaml up -d --no-deps app
```

`.player-demo.env` содержит `PLAYER_DEMO_ENABLED=true`, `PLAYER_DEMO_IMAGE=animonster-app:sitemap-fix-20261026` и путь `PLAYER_DEMO_CATALOG`; производственные секреты берутся из сохранённого окружения сайта. Nginx на старом сервере использует символическую ссылку с именем `animonster-maintenance`, которая фактически указывает на `sites-available/animonster-app`: перед изменениями всегда проверять цель ссылки.

Откат: `PLAYER_DEMO_ENABLED=false` и пересоздание только app; при необходимости вернуть предыдущий образ и Compose-каталог. Файлы БД, старые миграции, платёжные флаги и действующую схему прокси при откате не менять. Серверный торрент остановить командой `systemctl stop animonster-demo-torrent`; импорт — `systemctl stop animonster-media-import@rezero`.

## Быстрый вывод сезонов и продолжений

Выпуск `fast-relations-20261025` убирает из пользовательского запроса последовательное обновление до 12 тайтлов и ожидание уточнения названий/дат. `animeRelations` читает локальные связи и JSON только нужной франшизы. API и серверная страница хронологии планируют обновление через Next.js after; повторные задачи одного тайтла/франшизы объединяются. Обновление внешних связей выполняется атомарно: сбой HTTP, неверный JSON или ошибка записи не удаляют сохранённые сезоны. Пауза повторов после ошибки — 15 минут.

Ответ сообщает refreshing; пока данные дополняются, он не кэшируется. Клиент сразу показывает сохранённые карточки, проверяет обновление не более восьми раз с интервалом 5 секунд и сохраняет карточки при сбое/повторе.
