# QR login

Login dialog now offers a QR code generated locally with `qrcode`, without an external QR image service. A signed-in phone opens `/auth/qr` and explicitly approves the device after comparing the six-character code. Unauthenticated phones can use existing login methods; after social-provider redirects they should scan the code again. Email login can complete in the confirmation page's dialog. Browser/OS summaries are informational, not trusted proof of identity.

Requests expire after 120 seconds. Each request has independent random scan and initiating-browser secrets; only SHA-256 hashes are stored. The scan proof travels in a URL fragment, not a query string, is removed from the address bar on receipt and retained only in tab sessionStorage for a short-lived reload/login return. The browser proof is an HttpOnly, SameSite=Strict cookie scoped to `/api/auth/qr`, with a distinct cookie name per request. Production cookies are Secure. The API does not return either browser/session proof to JavaScript.

Scanning and approval never create a new login session by themselves. Only the initiating browser can consume an approved request. PostgreSQL row locks make approval/consumption single-use; concurrent completions create exactly one session. Consent binds the approving user and their active session. Suspension, deletion, required email verification, expired phone sessions or logout/password-session revocation prevent completion. An already authenticated browser cannot silently switch to another account through QR login. The resulting 30-day session uses the site's existing session inventory and cookie.

All API actions use POST, same-origin checks, JSON validation and persisted per-IP limits. Create requests are limited to 10 per ten minutes; other actions to 180 per minute. Cancel and phone-side denial prevent later completion. Expired old requests are cleaned during creation. All API responses are no-store. The confirmation page has private/no-store, no-referrer, DENY/frame-ancestors none and noindex headers; the URL never contains the desktop authentication proof. Yandex Metrika is excluded from the confirmation page, and the login QR block is marked `ym-hide-content`. No existing social-login provider configuration or account entitlements changed.
