# Бот сообщества ВКонтакте

Сообщество владельца: https://vk.ru/animonster1, `group_id=241950462`, имя AniMonster.su. Ключ проверен методами `groups.getById` и `groups.getTokenPermissions`: группа совпадает, право messages есть. Секрет хранится только на сервере `31.77.14.179` в `/root/animonster-vk-bot/community-token` (0600, каталог 0700), вне репозитория и Docker image. Это отдельный ключ сообщества, не секрет приложения входа через ВК.

## Возможности

- В профиле → Настройки → Уведомления появляется отдельный блок ВКонтакте.
- Сайт выдаёт одноразовую команду «Подключить …» на 15 минут. Пользователь сам открывает сообщения сообщества и отправляет команду. В БД хранится только хеш токена.
- Привязка допускается из личного входящего сообщения, после проверки разрешения `messages.isMessagesFromGroupAllowed`. ID существующего профиля ВК/другая активная привязка не могут быть присвоены чужому профилю AniMonster.
- После привязки доступна кнопка «Уведомлять ВКонтакте» на карточке. Без Plus — 3 тайтла в этом канале, с Plus — без лимита; подписки Telegram независимы.
- Название для подписки берётся из каталога на сервере. Неизвестный ID подписать нельзя.
- Уведомления создаются из сохранённой `anime_episode_availability`. Старые серии, впервые замеченные раньше подписки, не рассылаются. Учитывается время бесплатного доступа и действующая Plus-подписка.
- События callback дедуплицируются, привязка атомарная. Сообщение о подключении также ставится в долговременную очередь.
- Очередь ВК восстанавливает просроченный `sending` через 5 минут; разные воркеры используют lease с токеном. При повторе используется прежний `random_id` VK. Это уменьшает риск дублей, но не является обещанием exactly-once при любых сбоях/сроках дедупликации внешнего API.
- Обрабатываются ошибки VK внутри HTTP 200; временные ошибки повторяются с задержкой, запрет сообщений отключает доставку. Отписка/отключение отменяют ожидающие задания. Ошибки не сохраняют ключ или полное тело ответа VK.
- Telegram и его таблицы не мигрируются этой функциональностью. Найденное ранее отсутствие lease в Telegram остаётся отдельной задачей.

## Запуск на действующем сервере

Основной сайт работает на `177.3.218.227`. SSH-пароль root, предоставленный в предыдущем запросе, отклоняется. На момент подготовки кода доступ к этому узлу не получен, поэтому бот не объявляется подключённым на production. Сообщество имеет включённый Long Poll с `message_new`; Callback server 1 существует без URL, status=unconfigured. Настройки сообщества пока не изменялись.

1. Сохранить резервную копию БД. Применить `0071_vk_notifications.sql` существующим механизмом миграций. Это только новые таблицы/индексы; удалений или изменения пользовательских/платёжных таблиц нет.
2. Добавить в защищённую конфигурацию runtime:

   ```dotenv
   VK_BOT_ENABLED=true
   VK_BOT_GROUP_ID=241950462
   VK_BOT_TOKEN=<ключ сообщества, не коммитить>
   VK_BOT_SECRET=<случайный секрет 24–50 символов>
   VK_BOT_CONFIRMATION=<результат groups.getCallbackConfirmationCode>
   ```

   `VK_CLIENT_ID` и `VK_CLIENT_SECRET` относятся к авторизации и сохраняются. Пока `VK_BOT_ENABLED` не true, запросы к таблицам ВК не выполняются, интерфейс сообщает о недоступности бота. Для закрытой копии используются отдельная БД и отдельный env-файл.
3. Собрать и запустить новый образ. До изменения Callback API проверить локально `POST /api/vk-notifications/callback` с type=confirmation, group_id и секретом: ответ должен быть plain text с confirmation code. Неверный секрет/ID сообщества должны давать 404.
4. В настройках сообщества указать HTTPS callback `https://animonster.su/api/vk-notifications/callback`, тот же secret, версию 5.199. Включить только `message_new`, `message_allow`, `message_deny`. Существующие работающие интеграции/Long Poll не отключать без проверки.
5. Для доставки использовать существующий Plus worker (он вызывает обработку ВК) либо отдельный таймер:

   ```sh
   install -m 0755 deploy/animonster-vk-worker /usr/local/bin/animonster-vk-worker
   install -m 0644 deploy/animonster-vk-worker.service /etc/systemd/system/
   install -m 0644 deploy/animonster-vk-worker.timer /etc/systemd/system/
   # При нестандартном пути проекта задать ANIMONSTER_APP_DIR в systemd override.
   systemctl daemon-reload
   systemctl enable --now animonster-vk-worker.timer
   ```

   В runtime должен быть `RECOMMENDATION_CRON_SECRET` не короче 32 символов. Отдельный endpoint `/api/internal/vk-notifications` защищён этим секретом. Таймер ВК не выполняет платёжные/боевые пропуски/другие задачи Plus. Сохранённая доступность серий должна продолжать обновляться штатными Kodik/Plus процессами; таймер доставки сам не опрашивает видеопровайдера.
6. Владелец подключает свой профиль и выбирает один тайтл; проверить welcome, запись очереди и разрешённую тестовую доставку именно владельцу. Массовую очередь ради проверки не запускать.

## Контроль и отключение

Проверять только агрегаты, не публикуя recipient_id и содержимое личных сообщений:

```sql
SELECT status,count(*) FROM vk_bot_outbox GROUP BY status;
SELECT count(*) FROM vk_bot_outbox WHERE status='sending' AND claimed_at < extract(epoch FROM now())*1000-300000;
SELECT count(*) FROM vk_bot_accounts WHERE vk_user_id IS NOT NULL AND disabled_at IS NULL;
```

Для отключения установить `VK_BOT_ENABLED=false`, перезапустить только приложение и остановить отдельный таймер ВК, если он установлен. Данные и подписки остаются. При откате образа новые таблицы можно оставить; разрушительный откат миграции не требуется.
