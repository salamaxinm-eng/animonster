# Сборы AniMonster

Перед выпуском сделайте резервную копию PostgreSQL и примените миграцию
`0037_fundraising_goals.sql` штатным `npm run db:migrate` либо контейнером `migrate`.
Также примените `0038_admin_cosmetic_inventory.sql` для явной административной
выдачи коллекции владельцу.
Миграция и версия приложения должны выпускаться вместе.

## Данные и сохранение прошлого сбора

`fundraising_goals` хранит название, описание, короткую подпись переключателя,
целевую сумму в рублях, активность, порядок и связанный набор наград.
Начальные цели: `player` — 60 000 ₽, `development` — 20 000 ₽.
Все исторические заказы получают `fundraising_goal_id='player'`; их суммы,
статусы и Plus-доступ не меняются. Подтверждённым нетестовым старым платежам
выдаётся набор плеера, без автоматического экипирования.

Собранная сумма вычисляется по `orders` каждой цели:
`status='succeeded' AND NOT is_test`. Счётчика, который мог бы увеличиться
дважды при повторном webhook, нет. Общий рейтинг поддержки по-прежнему
учитывает успешные платежи всех направлений. Старые поля `goal` и `raised`
в API статистики сохранены для предыдущих клиентов и относятся к плееру.

## Оплата и награды

Прямая поддержка использует новый `plan='donation'`, сумму от 150 до 100 000 ₽
и `duration_days=0`. Покупки Plus сохраняют цены и сроки и тоже позволяют
выбрать цель. Без указания цели старые Plus-клиенты используют `player`.
Платежи доступны после входа; пользователя сервер получает из сессии.
Поле `userId` браузера не используется.

Webhook сохраняет существующую проверку секретных заголовков и повторную
проверку транзакции через API провайдера. Подтверждение заказа, Plus-доступ,
годовой тег и `grant_fundraising_reward(order_id)` находятся в одной
транзакции. При ошибке любой выдачи всё подтверждение откатывается,
возвращается ошибка, повторный callback может успешно повторить операцию.

Наборы описаны в `fundraising_reward_bundles` и `fundraising_reward_items`.
`player_supporter_bundle` даёт розовый пин, `development_supporter_bundle` —
синий. Теги тоже разные: розовый для плеера, синий для развития. Рамка и фон общие;
поддержка двух целей даёт шесть уникальных предметов. Пины и теги — прозрачные
PNG после удаления внешней подложки встроенным imagegen. Рамка и фон сохранены.
Миграция 0039 обновляет пути и добавляет розовый тег старым подтверждённым
сторонникам плеера; ранее полученные предметы и экипировка сохраняются.

Уникальность `fundraising_reward_grants(user_id,bundle_id)` предотвращает
повторную выдачу набора, `user_cosmetics(user_id,cosmetic_id)` — копии предметов.
Маркер набора создаётся после выдачи всех предметов. DB-триггер также запрещает
выдать эту косметику без связанного подтверждённого нетестового заказа.
Тестовые и preview-платежи не дают набор. Экипирование и снятие используют
существующий API косметики; выдача не меняет текущий стиль пользователя.

## Управление целями

Новые цели добавляются записью в `fundraising_goals`, без изменений страницы
или обработчика платежей. Набор опционален (`reward_bundle_id=NULL`).
Название кнопки задаётся `short_title`, сумма — `target_amount`.

Завершение сбора: `UPDATE fundraising_goals SET is_active=false WHERE slug=...`.
Статистика завершённого сбора остаётся доступной, новые платежи для него
отклоняются. Заказы, созданные до завершения, могут подтвердиться после него.
Награды продолжают храниться в инвентаре и работают без активного Plus.

## Проверка

`tests/fundraising.test.mjs` проверяет миграцию с существующими заказами,
независимость сумм, платёж от 150 ₽, отказ для 1–149 ₽, неподтверждённые и тестовые платежи,
повторные платежи/webhook, сохранность Plus, запрет чужой выдачи,
постоянное владение, экипирование/снятие и откат транзакции при ошибке.
Провайдер в тестах заменён заглушкой; реальные деньги не списываются.
Для production отдельно проверьте настоящий webhook в тестовом режиме
провайдера после выпуска.

## Административная коллекция владельца

По отдельному запросу владельца `scripts/grant-admin-cosmetics.sql` выдаёт
существующему администратору весь активный каталог с `source='admin'` и записью
в `moderation_actions`. Используйте `psql -v user_id=<UUID> -f scripts/grant-admin-cosmetics.sql`.
Скрипт не создаёт платежи, не увеличивает сборы, не назначает Founder, не меняет
достижения или экипировку. Повторный запуск не создаёт копии предметов.

Для защищённых косметических предметов DB-триггер требует, чтобы получатель
и указанный `admin_actor_id` имели роль `admin`. Обычным аккаунтам это исключение
недоступно. Публичный API косметики выполняет только экипирование/снятие.
Административное владение позволяет примерять также Plus и Founder-косметику
без подписки или занятия места в FOUNDING 10. Обычные платежи и награды
продолжают проходить исходные проверки.

## Исправление ассетов и суммы

`0039_support_asset_update.sql` разделяет теги и использует файлы `*-v2.png`.
Промпт встроенного imagegen: удалить только внешнюю прямоугольную подложку,
сохранить персонажа, текст Oni VIP / ANIMONSTER, декор и цвета; PNG с alpha.
Файлы: `public/rewards/support/{player,development}-{pin,tag}-v2.png`.
Минимум нового прямого доната — 150 ₽ (единая константа для backend и input).
Исторические платежи меньшей суммы сохраняются; цены Plus не меняются.
